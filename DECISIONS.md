# Decisions

## ADR-011 Development provider fallback
Use deterministic mock intelligence in development so external service availability, cost and credentials do not block the audited workflow. It emits explicitly non-authoritative outputs and source references. Replace through provider interfaces.

## ADR-012 Source authorization APPROVED 2026-09-25
**Initial APPROVED source list:** Empty. All new sources enter at DRAFT status. An ADMIN must explicitly advance each source to APPROVED before scheduled collection begins. Each source transition emits an audit row with actor=admin for the accountability log.
**Collector types authorized:** RSS 2.0 and Atom only. No arbitrary HTML scraping or unstructured URL fetching at this phase. Structured JSON API collectors require a separate ADR before activation.
**Collection cadence:** Minimum polling interval 15 minutes. Default 60 minutes. ADMIN may set per-source intervals between 15 minutes and 24 hours. Breaking-news 5-minute intervals are not permitted in this phase to reduce source-server impact and legal risk.
**Source retirement:** Retired sources are retained in the registry for audit continuity but never re-ingested. Disabled sources may be reactivated only after a new ADMIN approval cycle.

## ADR-013 Citizen PII and media APPROVED 2026-09-25
**Consent model:** Explicit, unbundled opt-in required at submission time (consent:boolean in the SubmissionIn schema). Consent is recorded as an immutable audit event (action=CITIZEN_SUBMITTED) and echoed back in the submission receipt. No consent → submission is rejected with 422. Consent text presented to citizens must include a plain-language description of retention, deletion rights, and data recipients.
**Submission text + metadata retention:** 7 years from date of submission. Aligned with standard public-records retention for investigative case files. After 7 years, submissions without an associated PUBLISHED finding are marked for review and may be anonymized or deleted by ADMIN. Submissions that contributed to a PUBLISHED finding are retained permanently as part of the provenance chain.
**Media references:** Citizen-provided media_reference fields are stored as references (URLs/hashes) only. Binary media objects must not be persisted to the relational database in Phase 1. If object storage is configured in Phase 3, media retention follows the same 7-year rule as submission text.
**Storage region:** United States. All production persistence (PostgreSQL, object storage, Redis) must provision in a US-based region. Cross-region replication is permitted only to a secondary US region for disaster recovery.
**Deletion process (Right to Erasure):** Citizens may request deletion of their submission by submitting the original submission ID plus a verified ownership proof (e.g., email confirmation link for Phase 2). ADMIN processes deletion requests within 30 calendar days. Deletion is soft-delete (status=DELETED, content fields nulled) for 90 days to satisfy audit lookback, then hard-delete. Audit rows referencing the submission are retained with the PII fields redacted to preserve the accountability chain. Deletion emits audit action=CITIZEN_DELETION_COMPLETED.
**Abuse process:** Submissions flagged by automated heuristics (duplicate URL flood, known-malicious domain patterns, keyword triage) route to status=REVIEW_HOLD instead of the default AI_ASSISTED_ANALYSIS. An ANALYST must review REVIEW_HOLD items before escalation. Repeat-abuse submitter identifiers (sub claim, IP hash) may be rate-limited by ADMIN but not silently blocked — blocked submissions must return 429 with an appeal contact.

## ADR-014 Finding and escalation policy APPROVED 2026-09-25
**Finding taxonomy:** Primary severity axis + category tag set. Severity: UNCLASSIFIED / LOW / MODERATE / SIGNIFICANT / HIGH / CRITICAL. UNCLASSIFIED is the default at publish time; ADMIN or PUBLISHER may upgrade severity on update. Category tags (multi-select, free-form with suggested vocabulary): FINANCIAL, PUBLIC_SAFETY, ENVIRONMENT, ETHICS, ADMINISTRATIVE, PROCUREMENT, ELECTIONS, HEALTH.
**Reviewer independence (separation of duties):** A user may not both submit an investigation for review (ANALYST role action) and also act as its REVIEWER. Backend enforcement: The review endpoint rejects with 409 when the audit trail shows the same actor created the INVESTIGATION_SUBMITTED event. UI hints warn before submission. REVIEWER ↔ PUBLISHER separation is also enforced: the PUBLISHER who releases a finding must not be the same account that reviewed it. Conflict-of-interest declarations are stored via a free-text note field on the FindingVersion record (actor note).
**Publisher authority:** Only the PUBLISHER role may transition findings to PUBLISHED or UNPUBLISHED status. Each publish or unpublish action creates a FindingVersion row with version++, actor, and note. PUBLISHERs cannot create evidence or approve investigations — those remain ANALYST + REVIEWER authorities. ADMIN has override authority for emergency retractions only and must log a mandatory retraction note.
**Escalation thresholds (citizen → investigation):** MANUAL BUTTON ONLY (already enforced in API — AI never auto-escalates). The citizen-facing escalate button is always enabled regardless of AI confidence. To guide ANALYST triage, the workflow decorates submissions with signals: (a) LLM uncertainty level from the analyze() call — "low" uncertainty submissions bubble to the top of the pending work queue; (b) published evidence match count — ≥3 matching PUBLISHED evidence items triggers a priority tag; (c) repeat submission (same URL, same submitter within 24h) → REVIEW_HOLD and deduplicate. Automatic server-side escalation is explicitly forbidden by this ADR and must remain so until a separate safety-evaluation ADR is approved.
**Escalation thresholds (investigation → publication):** Mandatory gating chain: ANALYST_SUBMISSION → (REVIEWER APPROVE or REVIEWER RETURN_TO_ANALYST) → PUBLISHER PUBLISH. Bypassing REVIEWER requires ADMIN emergency override with a mandatory 3-character minimum justification. No role shortcut may skip the PUBLISHER gate for public release.
