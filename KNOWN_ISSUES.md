# Known Issues

- No source is yet authorized for live collection; development uses synthetic fixtures only. Scheduler RSS hooks exist but return empty for non-APPROVED sources.
- Mock providers are the default and are intentionally non-authoritative. Real providers (Ollama, Hugging Face Inference, OpenRouter) are wired through env-var factories but have not been tested against live endpoints in this session. All adapters carry strict timeout (AI_TIMEOUT_SECONDS=10), credential-presence checks, and transport-level exception handling that falls back to Mock providers on any failure — so production errors degrade gracefully rather than throwing.
- PostgreSQL migrations via Alembic are configured; revisions 0001_initial (10 tables), 0002_knowledge_layer (finding_versions + evidence_relations), and Embeddings model (via init_db create_all) are collectively compatible with both SQLite and Postgres dialects. Alembic upgrade head --sql OFFLINE validated against PostgresqlImpl context and produced valid DDL (TIMESTAMP WITH TIME ZONE, UniqueConstraint on evidence_relations, ix_documents_content_hash unique index, version-bookend UPDATE alembic_version). ONLINE Postgres migration validation is PENDING — local PostgreSQL 18.3 service is Running but auth method is scram-sha-256, password unknown, service reload requires admin permissions (Restart-Service permission denied). pg_hba.conf was modified to trust but requires effective reload/Postgres restart. Postgres password or admin UAC is needed for online Alembic tests.
- Docker Compose declares PostgreSQL 16-alpine + Redis 7-alpine + API image with postgresql+psycopg DSN, but Docker daemon is not installed/running on this system so online compose validation is blocked until Docker is installed or the user supplies a remote Docker host.
- Redis streams consumer is implemented and auto-selects transport (Redis-first, DB-fallback). Redis server itself has not been started or integration-tested in this session; the in-process fallback covers the MVP. DLQ operations on the DB layer are fully functional without Redis.
- pnpm supply-chain policy gates native build scripts for sharp@0.34.5 (ERR_PNPM_IGNORED_BUILDS). This does not affect TypeScript checks but the Next.js production build should either run `pnpm approve-builds sharp` or `pnpm build --ignore-scripts`.
- Embedding vectors currently stored as JSON column in `embeddings` table (1 vector per collection+entity via UniqueConstraint). Works fine for <10k rows MVP. For >10k rows with PostgreSQL, migration to pgvector column type + HNSW/IVFFlat index is recommended; the current pure-Python cosine_similarity rerank on K=4*limit candidate sets is linear and will slow.
- Semantic sort in POST /analyst/search is a two-phase approach: top K=4*limit candidates recalled by newest-first (or ilike match), then reranked by Python cosine_similarity in-process. For high volume this should be replaced with pgvector ANN. Semantic rerank flags returned per collection (`semantic_reranked: bool`) and per-item (`semantic_score: float`).
- Analyst search investigations semantic rerank recomputes Submission via `s.get(Submission, id)` inside per-row lambda. For 100-row candidate sets this is fine; for larger K, preload submissions into a dict keyed by investigation.submission_id outside the lambda to avoid N+1.
- AI-bounded worker hook `_apply_bounded_ai_job()` currently only emits audit trail attribution rows (actor=ai-worker/{provider}) for AI-prefixed event types. It does NOT perform real downstream AI work (e.g., document extraction, evidence scoring) yet. Real AI jobs can be added inside the same handler once the work items are designed.
- AI_WORKER Role enum value exists but is only used as audit actor label; no HTTP endpoint trusts x-role=AI_WORKER for mutation. AI outputs do not auto-escalate, auto-approve, or auto-publish anything — citizen submission status still flips only on published human-reviewed evidence match; escalations and approvals are exclusively button-triggered by real human roles (ANALYST/REVIEWER/PUBLISHER/ADMIN). Guarding: keep this pattern as new AI jobs are added — never let x-role=AI_WORKER mutate findings/source status or publish evidence.
- Worker CANCELLED outbox status is supported in outbox persistence layer but not explicitly included in worker_status() count totals (only PENDING/DISPATCHED/DEAD counted). Operations endpoints for cancel/get/retry/count work correctly.
- Frontend auth strategy PUBLIC-CLEAN as of v0.6.2: routes `/`, `/findings`, `/findings/[id]` now send NO x-role headers at all and consume `/public/*` endpoints only, production-ready for anonymous public visitors out of the box. Remaining role-gated routes: `/admin/sources` (x-role=ADMIN + visible AUTH TODO banner), `/room` (x-role=ANALYST + visible AUTH TODO banner), `/admin/search` (x-role=ANALYST + visible AUTH TODO banner). A production authentication layer (JWT, OAuth, session) has NOT been integrated. These 3 admin/analyst routes must have a real auth middleware before any public exposure.
- Analyst-only UNPUBLISHED finding access: since `/findings/[id]` was converted to PUBLIC (no x-role header, returns 401/403 clean UI for unpublished), analysts currently need to view unpublished findings via `/room` Situation Room investigation links or direct API access. An analyst-facing `/analyst/findings/[id]` route or dual-mode same-route variant should be built for production analyst workflow that reads real auth credentials.
- Source governance admin route status filter counts recalculate client-side from full downloaded array (`allSources.filter(…).length`); works fine for MVP, will need server-side count endpoints at scale.
- Next.js App Router `params.id` in `/findings/[id]` uses `decodeURIComponent` for safety; if finding IDs ever contain URL-reserved characters they will still be handled.
- Ollama LLM adapter uses /api/generate single-turn prompt, not /api/chat. For multi-turn conversation features this should be swapped to /api/chat with message array format.
- Hugging Face Inference Providers URLs used are from 2026-09-22 docs (router.huggingface.co/hf-inference/models/{model}/v1/...). If HF changes the router path, update provider URLs — adapters will gracefully fall back to Mock and log warnings.
- OpenRouter attribution headers (HTTP-Referer + X-Title) are hardcoded to `https://aipieisr.local` / `AIPEIISR`. Change these to real public URLs before production deployment per OpenRouter ToS.

Multi-collection pagination uses max(bag.total across collections) as the disable-threshold upper bound for Next button (good enough MVP analyst tooling; not per-collection independent offsets).
- Situation Room provider cards: state detection is best-effort name-based string parse (Mock/Ollama/HF/OpenRouter/GPT/Gemini etc.) — not live HTTP pings. Provider cards show "Live · {name}" green even if the underlying provider has real network errors because provider name is set at factory import time. For true live-ping status, add per-provider ping-timeout or heartbeat fields to /health response and color cards accordingly.
- Public findings browser /findings fetches GET /public/findings with fixed limit=10 per page (not exposed as user selectable control yet). If higher page sizes are needed for analyst cross-viewing, add limit selector similar to analyst search Top-N dropdown.
